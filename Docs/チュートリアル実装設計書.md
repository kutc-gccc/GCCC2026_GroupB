# チュートリアル実装設計書

作成日：2026-10-26 ／ 状態：実装済み（コンパイル確認済み、Unity再生確認は未実施）

## 1. 目的と対象

配信の予行練習として、移動、ダッシュ、メッセージ画面、タスク受注、懐中電灯の操作を順番に体験し、本編のフェーズ1へ進む。

参照：`F:/gameseisaku/設計図/設計図.xlsx`「チュートリアル」シート3～17行。シート内の文言・時間・表示要求はゲーム仕様の資料として扱う。本書の「提案」は資料で決まっていない部分の補完であり、確定仕様と区別する。

対象はタイトル `Assets/Scenes/Title.unity` の開始選択、専用シーン `Assets/Scenes/subji/Tutorial.unity`、本編 `Assets/Scenes/subji/jikkennsupace.unity` への接続。専用シーンは既存マップとUIを再利用して作成した。

実装：`JikkenCommentStream.Tutorial.cs` に工程設定・進行を集約。本書の提案値を初期値として採用し、コメント・秒数・送り主・色と単独プレイ後の本編遷移はInspectorで調整できる。移動・ダッシュは既存の操作を再利用し、開画面・点灯の判定はキャッシュ済み参照から状態を読む。

### 追加確定仕様（2026-10-26）

- チュートリアル開始時から終了まで、ゲーム内の暗闇表示を無効にしてマップ全体を明るくする。懐中電灯の点灯・消灯にかかわらず明るさを維持する。
- チュートリアル中の敵は0体。通常敵・監視敵を非アクティブにし、スポーナーによる追加出現も停止する。追跡だけの停止では済ませない。
- ライト練習は明るい状態のまま、受注後の点灯操作で達成を判定する。
- 終了時の画面演出としての暗転は、ゲーム内の暗闇とは別に扱う。本編開始時に通常の暗闇表示とフェーズ1の敵構成（通常2体・監視0体）へ切り替える。

### タイトルからの開始選択（確定仕様）

タイトルのSTARTボタンを押した時点ではゲームを開始せず、「チュートリアルをプレイしますか？」という選択画面を表示する。

| 選択ボタン | 開始内容 |
| --- | --- |
| チュートリアルをプレイ | 専用のTutorialシーンを読み込み、明るい状態・敵0体でT00から開始する。完了後に本編へ進む |
| スキップして本編へ | 通常マップを読み込み、通常の暗闇・通常敵2体・監視敵0体で本編タスクID1から開始する |

未選択のままでは遷移しない。スキップ時は練習用コメント・練習タスク・OK表示・チュートリアル終了の5秒暗転を実行しない。選択確定後は両ボタンを無効にし、多重遷移を防ぐ。

確定仕様：チュートリアルをプレイした場合もスキップした場合も、本編の開始地点は同じとする。本編シーンに保存されたプレイヤーの初期配置を共通の開始地点として使う。チュートリアルで移動した位置を引き継がず、本編シーンを新たに読み込んで開始する。

実装方針：`Assets/Title/TitleMenu.cs` のSTARTによる即時シーン遷移を選択画面の表示へ置き換える。選択に応じてTutorialまたは本編シーンを読み込む。Tutorialではチュートリアル、本編ではフェーズ1を開始し、本編側で導入を再実行しない。開始方法は今回の起動にのみ適用し、初回済み保存や次回の自動スキップは追加しない。

確定仕様：UnityでTutorialシーンを直接再生しても、タイトルや本編を経由せずチュートリアルをT00からプレイできる。本編シーンを直接再生した場合は本編から始める。タイトルへ戻ってSTARTを押した場合は毎回選び直せるよう、一時的な選択状態を残さない。

単独プレイ時の終了方法（提案）：TutorialのInspectorに「完了後に本編へ進む」を設け、単独再生ではオフを初期値とする。オフの場合は終了案内を表示してチュートリアルを完了し、本編の読込・5秒暗転は行わない。タイトルから選んだ場合は今回の起動に限りオンにして、従来の指定どおり完了後に本編へ進む。

### Spaceによるコメント送り（確定仕様）

- チュートリアル中はSpaceを1回押すと、表示中のコメントを1つ飛ばして次の工程へ進む。説明コメントと操作待ちの問題コメントの両方を対象とする。
- 押した瞬間だけ受け付け、長押しでは連続して飛ばさない。同じ入力で次のコメントまで飛ばさない。
- 表示時間や操作条件が未達でも進める。飛ばした問題にOKや報酬を出さず、残りの待機時間・計測・達成待ちを解除する。OK表示中のSpaceは次のコメントへ進める。
- メッセージ画面を開いていても使用できる。ポーズ中・終了暗転中・本編開始後はこのコメント送りを受け付けない。
- T09を飛ばして画面を開いていない場合も、T10以降の案内を表示し、必要なら通常操作で画面を開ける。T12を飛ばしてもT13の練習が可能なよう、未受注なら同じ練習タスクを報酬なしで内部的に受注する。タスクを重複生成しない。
- T13を飛ばす場合は練習タスクを報酬なしで解除して終了案内へ進む。T14を飛ばす場合は終了暗転を開始し、本編への接続処理は通常どおり行う。

Spaceによる送りは現在の工程の案内だけを進め、本編タスクの達成や次ID進行には使用しない。

## 4. 達成条件と入力

### 移動・ダッシュ

- 計測開始は各問題の表示時。説明中の先行操作は加算しない。
- 移動の累計時間は、操作可能かつ実際に移動しているフレームだけ加算する。停止しても累計を保持する。
- ダッシュは移動処理が採用したダッシュ状態を使う。Shift単独、ゲージ切れ、移動ロック中は加算しない。
- 壁に押し付ける入力を移動として数えない案を採用する。最小移動量は既存の移動処理に合わせ、微小な位置ずれを除外する。
- ポーズ中は計測・時間経過を停止する。OK待ち中に次の問題の計測を始めない。

### メッセージ画面

- 選択だけでは達成しない。`OpenCommentScreen` による実際の開画面を検知する。
- 提案：ホイール操作そのものは必須にせず、問題中に画面を開ければ達成とする。誤って先に開いた場合も閉じて開き直せる。
- メッセージ画面を開く既存操作を変更しない。開画面中のミニマップ非表示も既存仕様に従う。
- T10以降で閉じてしまっても、同じ操作で再度開いて続けられる。

### 練習タスク・点灯

- 練習タスクは本編ID1～8と区別する識別子を持つ。本編の次ID進行を発生させない。
- 表示、単一選択制限、受注色、完了色、解除は `JikkenCommentStream` の共通処理を使う。
- 提案：T10・T11中は練習タスクを表示するが受注を無効にし、T12で有効にする。説明前のクリックによる工程飛ばしを防ぐ。
- T12達成後のOK待ちは、原表に時間指定がないため3秒を提案する。受注は一度だけ処理する。
- T13ではメッセージ画面を閉じてからライトを操作する。UI上のクリックを点灯操作として扱わない。
- 原表の対象はプレイヤーの懐中電灯。コーヒーカップなどの設備ライトと混同しない。
- 提案：受注時にライトが点灯済みなら練習用に消灯し、受注後の点灯操作で達成する。事前点灯による自動達成を防ぐ。
- 提案：練習タスクの報酬は0人。本編ID1～3の各100人報酬は維持する。

## 5. 画面表示と調整項目

既存のコメント履歴・ポップアップを再利用する。メッセージ画面が閉じていても現在の案内を読めるようにする。中央のOK表示は既存UIへ最小限追加し、操作を遮らない。

Hierarchyの `Jikken Comment Stream` のInspectorで、各工程の文言、送り主、説明時間、必要操作秒数、OK表示時間、通常色・問題色・OK色、終了案内時間、暗転時間を調整できる構成にする。工程設定を一か所にまとめ、状態番号ごとの固定値を散在させない。

時間の初期値：導入3秒、通常説明3秒、移動4秒、ダッシュ2秒、OK3秒、暗転から本編まで5秒。

原表で未指定の提案値：終了案内3秒、暗転のフェード0.5秒。終了案内の後に暗転を開始し、暗転開始から合計5秒で本編を開始する。数値はInspectorで変更できるようにする。

## 6. 専用シーンと本編への接続

Tutorialは独立したシーンとし、プレイヤー、カメラ、移動・ダッシュ・ライト、タスクバー、コメント・タスクUI、必要な床と衝突判定を持つ。タイトル側の初期化や本編の配置オブジェクトを必須参照にしない。本編専用の噴水・汽車・ポータルがなくても開始できるよう、初期化を練習と本編に分ける。新しい敵や設備は配置しない。

タイトルからチュートリアルを選んだ場合は、次の流れで接続する。

1. 練習完了後に終了案内を表示する。
2. 案内終了で暗転を開始。移動とアイテム操作をロックし、メッセージ画面を閉じる。
3. 暗転開始から5秒後に本編シーンを読み込む。シーン読込に時間がかかる場合は準備ができるまで暗転を維持する。
4. 本編シーンに保存された初期配置でプレイヤーを開始し、通常の暗闇・通常敵2体・監視敵0体を適用する。
5. 暗転を解除し、本編ID1を1回提示する。練習の座標・タスク・コメント・操作ロックを持ち越さない。

確定仕様：Tutorial内の敵は0体。敵とスポーナーを配置しない構成を基本とし、再利用元に含まれる場合は無効化する。本編側は既存の共通敵数管理を使用する。Tutorial単独プレイの終了方法は前述の提案に従う。
提案：練習中は本編タスクの提示、購入・ポータル移動を抑止し、進行を妨げないようにする。

登録者の自然増加を練習中にも動かすかは設計図に記載がない。初期案は既存挙動を維持し、勝手に数値をリセットしない。専用シーンの練習マップは必要な範囲のみ用意し、初回済み保存は追加しない。スキップはタイトルの開始選択から行う。

## 9. 実装時に採用可否を決める提案

原表にないため、本書では「累計ダッシュ」「T12後の3秒待ち」「練習報酬0人」「受注時の消灯」「説明中の受注抑止」「単独プレイ時の完了後遷移設定」「練習中の購入・ポータル抑止」「終了案内3秒・フェード0.5秒」を提案した。実装依頼時はこれらを設計案として確認し、ユーザーの追加指定を優先する。明るい状態での開始・維持、敵0体、タイトルでの開始選択、本編開始地点の統一、チュートリアル専用シーンと単独再生はユーザー指定の確定仕様とする。
