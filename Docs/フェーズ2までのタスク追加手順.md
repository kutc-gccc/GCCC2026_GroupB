# フェーズ2までのタスク追加手順

この文書は実装手順と仕様の記録です。フェーズ1・2の共通処理と対象参照は実装済みです。

通常の調整は、Hierarchyの`Jikken Comment Stream`を選び、`JikkenCommentStream`の「フェーズ1・2 共通設定」「導入コメントの時間」で行います。操作地点は`Phase 1-2 Task Points`配下で移動できます。汽笛は既存の汽車（いろいろ2_14）手前の操作地点に接続しています。見た目の追加は行いません。

対象を再設定する場合のみ、Unity上部の`Tools > Tasks > フェーズ2までの対象を設定`を使用します。既存の操作地点は再実行しても移動しません。`フェーズ2設定を検証`で参照・敵の必要数・屋内シーン登録を確認できます。

お化け屋敷は既存の屋内シーンのゴールへ到達すれば達成します。追加の調査地点・人形・調査フラグは使用しません。

動作確認は`Tools > Tasks > フェーズ2の動作を検証（Play Mode）`から再実行できます（Ctrl+Shift+F9）。検証中は自動操作し、終了後にPlay Modeを停止します。テスト中の位置・タスク・報酬・敵への変更はシーンへ保存しません。成功時のConsoleログは`PHASE_TWO_PLAYMODE_OK`です。

初回実装時の確認（ゴール簡略化後はコンパイル確認済み、再生テスト未実施）：噴水到達、自販機1秒・ブッシュ0.5秒のE単押し、フェーズ2の抽選と敵数、QTEの誤入力・正解入力、3秒乗車と途中下車防止、既存の屋内ゴール到達、汽笛の移動キャンセル・2秒反応・4秒完了、タスク報酬の加算。テストでは衝突事故を避けるため敵の動作を停止し、通常プレイの経路移動と難易度調整は別途行います。登録者の毎秒自然増加は既存の設定を維持しています。

## 1. 今回追加する仕様

| フェーズ | ID | 内容 | 達成条件 | 登録者報酬 |
|---|---|---|---|---|
| 1 | 1 | 噴水広場に行こう | 指定地点へ到達 | 100人 |
| 1 | 2 | 自販機でジュースを買おう | 自販機付近でEを1回押して1秒経過 | 100人 |
| 1 | 3 | ブッシュの中に隠れよう | ブッシュ付近でEを1回押して0.5秒後に隠れる | 100人 |
| 2 | 5 | 壁にサインして | 矢印キーを ↑ ↓ ← ↓ ↓ → の順で入力 | 5,000人 |
| 2 | 6 | フリーーーーフォール!! | 乗車して3秒経過 | 5,000人 |
| 2 | 7 | お化け屋敷の潜入調査 | お化け屋敷の既存ゴールへ到達 | 5,000人 |
| 2 | 8 | 車掌さんごっこ | 電車付近でEを1回押して4秒経過 | 5,000人 |

- ID4は保留。欠番のまま残し、後日追加する。
- フェーズ1はID1→2→3の順で進める。
- フェーズ2はID5～8から3つを達成する。ID7は必ず出現し、出現順はランダム。
- 敵の合計はフェーズ1が通常敵2体、フェーズ2が通常敵4体・監視敵3体。
- 汽笛はEを1回押すと開始し、進行中にループ再生する。開始から2秒で警備員を誘導し、4秒で達成して音を停止する。キャンセル時も停止する。
- フリーフォールは途中下車不可。乗車中は警備員が近づかない。
- エンディングとフェーズ3以降は今回の対象外。

## 2. 作業前に確認するもの

1. 使用するゲームシーンを複製またはバージョン管理で保存する。対象シーンは実際にゲームを開始するシーンを選ぶ。
2. Hierarchyでプレイヤー、`JikkenCommentStream`、自販機、ブッシュ、敵を確認する。
3. 次の既存処理を再利用する。

| スクリプト | 再利用する役割 |
|---|---|
| `Assets/Scripts/Subji/JikkenCommentStream.cs` | コメント、単一タスク選択、タスク表示、ミニマップ、報酬、完了処理 |
| `Assets/Scripts/Subji/TimedWorldInteraction.cs` | 時間計測、ゲージ、移動ロックとキャンセル |
| `Assets/Scripts/UI/DrinkItemController.cs` | 自販機の購入と購入完了通知 |
| `Assets/Scripts/Subji/BushHideSpot2D.cs` | 隠れる・出る操作、隠れ状態、入った際の通知 |
| `Assets/Scripts/Subji/SubjiEnemyChase.cs` | 敵の索敵・追跡・帰還・接触処理 |

既存の`TimedWorldInteraction`の「Eを1回押すと開始し、離しても時間経過で完了する」方式をそのまま使用する。自販機とブッシュの現在の既定時間は両方2秒なので、指定時間へ変更する。

## 3. 同じHierarchyオブジェクトに設定をまとめる

既存の`JikkenCommentStream`が付いているGameObjectを設定の入口とする。新たな設定クラスを作る前に、このコンポーネントへのシリアライズ項目追加で対応できるか確認する。

以下は追加する項目の案で、現状のInspectorにすべて存在するわけではない。

| 設定 | 初期値 |
|---|---|
| 自販機の操作時間 | 1秒 |
| ブッシュの操作時間 | 0.5秒 |
| フリーフォール乗車時間 | 3秒 |
| 汽笛の達成時間 | 4秒 |
| 汽笛で警備員が反応する時間 | 2秒 |
| サインQTE入力順 | UpArrow、DownArrow、LeftArrow、DownArrow、DownArrow、RightArrow |
| 汽笛音 | `Assets/Resources/Audio/train_whistle.mp3` |
| 汽笛音量 | Inspectorで調整可能にする |
| 各タスクの対象・案内文・報酬 | 上表に合わせる |

設定値は開始時やタスク開始時に各対象へ渡す。自販機・ブッシュの値を毎フレーム上書きしない。複数の自販機・ブッシュがある場合も同じ共通値を使用する。

## 4. 時間付き操作を共通基盤で拡張する

1. `TimedWorldInteraction`の既存の時間経過方式を再利用する。Eを押した瞬間に開始し、キーを離しても継続する。
2. 自販機・ブッシュ・汽笛は移動入力でキャンセルする既存仕様を使用する。範囲外への移動や対象・プレイヤーの無効化時にも終了処理を行う。Eの解除ではキャンセルしない。
3. キャンセル・完了を呼び出し元へ通知できるようにする。汽笛の停止などはこの通知で行う。
4. 完了・キャンセルのどちらでも移動ロックとゲージを解除する。完了通知は1回だけ発生させる。
5. フリーフォールは自動進行方式を使い、乗車後のキー解除ではキャンセルしない。乗車中の移動入力でも降りられないよう、通常操作とキャンセル条件を分ける。
6. 既存のコーヒーカップなどの呼び出しが壊れないよう、従来の呼び出し方も維持する。

キャンセル時は既存処理と同様に進捗を0へ戻す。

## 5. フェーズとタスク進行をつなぎ替える

1. `JikkenCommentStream`内で設計上のタスクIDと、導入コメントのIDを分けて管理する。既存の「ID6・7」等の名称を、そのまま設計上のタスク番号と解釈しない。
2. 既存の`SelectTask`、`HasActiveTask`、`CompleteActiveTask`などを共用する。タスクごとにUI・報酬・完了処理を作り直さない。
3. ID1完了後にID2、ID2完了後にID3を選べるようにする。現在は自販機とブッシュのコメントが時間差で両方出るため、順次解放するよう変更する。
4. ID3完了後、従来のコーヒーカップ・城へ進む自動処理を今回の進行から外し、フェーズ2へ切り替える。
5. フェーズ2開始時にID7と、ID5・6・8から重複なしで2つを抽選し、3つの出現順をシャッフルする。
6. 3つ達成した時点で「フェーズ2完了」とする。今回はフェーズ3のタスクを開始しない。
7. 未選択のタスク操作で報酬や進行が発生しないよう、選択中のIDと達成通知を照合する。

手順5は「3タスクを選んで順次出す」実装案。4つとも提示して3つ達成する方式との違いは設計で未確定なので、抽選部分を差し替えやすくしておく。

## 6. フェーズ1の対象を設定する

### ID1：噴水

噴水の到達地点を設定用オブジェクトから参照させる。既存の到達判定とミニマップ表示を使用する。別の場所に配置しても座標のコード修正が不要な構造にする。

### ID2：自販機

既存の`DrinkItemController`へ共通設定の1秒を渡す。Eを1回押すと計測を開始し、1秒後の購入完了の`DrinkPurchased`通知でタスクを完了させる。購入処理と報酬が二重に発生しないことを確認する。

### ID3：ブッシュ

既存の`BushHideSpot2D`へ共通設定の0.5秒を渡す。隠れたときの`PlayerEnteredBush`通知で完了させる。隠れた後のEによる退出操作は維持する。

## 7. フェーズ2の対象を設定する

### ID5：壁のサイン

1. サインする壁に操作範囲を設定する。
2. タスク受諾後、範囲内でQTEを開始する。
3. 共通設定の入力順を読み、↑ ↓ ← ↓ ↓ →を1入力ずつ判定する。
4. 正しい入力の進捗を表示し、6入力完了で既存のタスク完了処理へ通知する。
5. 範囲外へ出たらQTEを終了する。キーの押しっぱなしで複数入力を消化しない。

誤入力・時間切れ・開始キーは未確定。実装時の仮仕様は「範囲内でEを押して開始、誤入力で先頭に戻る、制限時間なし」とし、確定仕様と区別する。Eの長押しは条件にしない。

### ID6：フリーフォール

1. 乗車地点と降車地点を配置し、対象から参照する。
2. タスク受諾後、乗車地点でEを押すと乗車する方式を仮置きする。
3. 共通時間処理で3秒計測する。乗車中は移動・別の操作・途中下車を禁止する。
4. 敵の共通処理へ乗車状態を伝え、乗車中は接近しないようにする。接触によるゲームオーバーも起こらないよう確認する。
5. 3秒後に降車地点へ移し、状態を戻してタスクを完了させる。無効化時にもロックが残らないようにする。

### ID7：お化け屋敷

既存の入退場処理を使い、屋内の既存ゴールへ到達して通常マップへ戻った通知でタスクを完了する。追加の調査地点・人形・通過順条件は設けない。

### ID8：汽笛

1. 電車に操作範囲と汽笛用`AudioSource`を設定する。
2. 音源に`train_whistle.mp3`を割り当て、`Play On Awake`をオフ、`Loop`をオンにする。音源は既にプロジェクトへ取り込み済み。汽車の画像は追加せず既存の汽車を使用する。
3. タスク受諾後、範囲内でEを押すと共通の時間経過処理と音の再生を開始する。Eを離しても継続する。
4. 音を毎フレーム再生し直さず、操作開始時に1回だけ`Play`する。
5. 操作開始から2秒に達したら、近くの警備員へ汽笛地点を調査するよう1回通知する。索敵・移動そのものは`SubjiEnemyChase`の共通基盤を使う。
6. 4秒でタスクを完了し、音を停止する。移動などで操作がキャンセルされた場合やオブジェクトが無効になる場合も必ず音を止める。
7. Eを押し続けても操作を再開始しない。報酬と誘導通知は繰り返さない。

## 8. 敵の配置を切り替える

1. 全敵を`SubjiEnemyChase`の共通基盤で設定する。新しい追跡スクリプトを敵ごとに作らない。
2. フェーズ1は通常敵2体を有効化する。
3. フェーズ2では通常敵が合計4体、監視敵が合計3体になるように切り替える。追加数と合計数を混同しない。
4. 現在の自販機・ブッシュ完了後の敵有効化処理と、自動スポーン処理が重複しないよう整理する。
5. 帰還先は各個体の開始位置を保存する。配置場所を変えても同じ基盤を使用する。

監視敵の細かな行動差と汽笛に反応する範囲・対象数は未確定。既存の敵設定で表現できる範囲から決める。

## 9. Unityで確認する

- Consoleにコンパイルエラーがなく、対象・音源参照が設定されている。
- ID1→2→3の順に解放され、ID4が出現しない。
- 自販機は1秒、ブッシュは0.5秒で完了する。Eをすぐ離しても継続し、移動入力でキャンセルされる。
- 選択タスクは常に1つで、案内・ミニマップ・完了色・報酬が連動する。
- フェーズ2にID7が必ず含まれ、重複しない3タスクが出現する。
- QTEが↑ ↓ ← ↓ ↓ →でのみ達成する。
- フリーフォールは3秒、途中下車不可で、乗車中に敵が近づかない。
- お化け屋敷は既存のゴールへ到達して達成する。
- 汽笛はEを1回押すとループ開始し、Eを離しても継続する。2秒で警備員が反応、4秒で1回だけ達成して停止する。移動キャンセルでも音が止まる。
- Hierarchyの同じ設定箇所で時間・QTE順・音源を変えると動作へ反映される。
- フェーズ1で通常敵2体、フェーズ2で通常敵4体・監視敵3体になっている。
- フェーズ2の3タスク達成で進行が止まり、従来の城やコーヒーカップのタスクへ進まない。

登録者は手順書では個別報酬方式を採用する。この場合、フェーズ1の増加は300人、フェーズ2は15,000人。設計図の「フェーズごとに一括管理」を報酬付与にも適用するかは未確定であり、両方式を併用して二重加算しない。
